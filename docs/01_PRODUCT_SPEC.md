# 产品行为与功能规格

## 1. 任务是整个软件的工作单位

任务保存源根目录、整理区域、排除规则、模板快照、分类树版本、模型配置快照、隐私授权、文件快照、用户审阅、执行计划与结果。修改全局模板或模型连接不会悄悄改变已启动任务。

同一应用同时只运行一个重型任务，可以排队；读取历史、编辑模板和查看设置不受影响。不同任务的源／目标目录若重叠，不能并行执行文件操作。

### 1.1 新建任务字段

| 字段 | 默认／约束 | 行为 |
|---|---|---|
| 名称 | 源文件夹名 + 日期，最长 80 字符 | 可编辑 |
| 源目录 | 单个用户显式授权的本地目录 | 不提供默认全盘扫描 |
| 扫描方式 | preserve_top_level | 三种方式见下文 |
| 操作方式 | preview_move | direct_move 需要高级授权 |
| 输出目录 | 移动默认在各整理区域内部；复制必须另选目标 | 目标不能被本次扫描重新纳入 |
| 整理策略 | hybrid | 三种策略均有独立说明与目录预览 |
| 分类来源 | auto_plan | 模板／固定类别／自然语言 |
| 分类模式 | rules_first | ai_first／rules_only 可选 |
| 最大目录深度 | 2 | 整数 1～3 |
| 同级目录上限 | 12 | 整数 2～20 |
| 每区域节点上限 | 80 | 整数 2～200 |
| 全任务新增目录上限 | 200 | 整数 10～1000；调高有资源提醒 |
| 文件范围 | 六类核心文件 | 其他格式默认保留原地 |
| 隐藏／系统文件 | 排除 | 不支持绕过系统目录保护 |
| 大文件 | 超过 2 GiB 提醒，不自动完整读取 | 可仅提取元数据／抽样 |
| 分析深度 | standard | fast／standard／deep |
| 未决处理 | keep_in_place | 不默认物理移动到待确认 |
| 同名冲突 | keep_both | 生成稳定后缀，不覆盖 |
| 上传原文件 | 关闭 | 仅可对白名单图片在逐项预览后开启 |
| 重命名内容文件 | 关闭 | 首版只因重名添加后缀，保留原主文件名 |

### 1.2 三种扫描方式，必须按这个定义实现

`current_only`：只纳入源目录的直接文件。子目录不解析、不移动、不计作文件候选。

`recursive`：源目录构成一个整理区域，所有符合条件的后代文件可跨原目录重新分类。默认不删除因此留下的空文件夹。

`preserve_top_level`：源目录内每个直接子目录各自构成独立整理区域；原一级目录名不变，不允许在区域之间移动。源根目录的直接文件构成一个单独的 root_loose 区域，该区域只包含这些直接文件，不吞并已有子目录。各区域内部可以递归读取。

例如选择 `D:\资料`，存在 `学习\网络\a.pdf`、`工作\b.docx` 和根目录 `c.jpg`。保留一级模式下 a 只能在 `学习` 内重组，b 只能在 `工作` 内重组，c 可归入根目录新建的生活类目录，但不能混入受保护的已有 `学习` 或 `工作` 区域。

**层级定义**：最大 2 级指整理区域之下新增的分类路径最多两段，不计源目录和被保护的一级目录。例如 `D:\资料\学习\计算机网络\实验报告\a.pdf` 合法；其中「学习」是保护区域，不是新分类层级。改变扫描方式必须重新显示实际完整路径。

复制到新目标时保留区域映射：`目标\学习\计算机网络\实验报告`；root_loose 直接映射到目标根。若名称冲突，源区域名保持固定，root_loose 的分类名称由规划器避让，不能合并保护区域。

### 1.3 排除与保护

始终排除应用安装／数据／缓存目录、本任务输出目录、当前任务创建的目录、符号链接／junction／reparse points、系统核心目录以及未实际下载的云端占位文件。首版不递归压缩包，不运行宏，不执行脚本，不访问文档内链接。

发现 `.git`、`package.json`、`pyproject.toml`、`node_modules`、`.venv`、常见软件安装标志时给出「疑似项目／程序目录」保护提示。默认跳过整棵相关目录，避免把资源文件拆散；允许未来单独做项目整理，不在首版强行理解工程结构。

用户可按目录、后缀、名称 glob 排除。规则变动后扫描快照失效，执行前需重新核对受影响文件。未支持格式和锁定文件在报告明确列出，不吞掉。

## 2. 分类产品行为

### 2.1 三种整理策略

模态优先：第一层固定为图片／文档／音频／视频／文本，剩余层级用于内容类别。只有 1 级时就停留于模态，不偷偷增加第二级。

主题优先：各种模态共享主题树；例如「旅行／行程资料」接纳 PDF、TXT，旅行照片进入同主题的照片节点。每份文件只有一个主类别。

智能混合：根据所选模板或用户目标生成主题树，必要时在第二层使用模态或用途。不能每文件临时发明结构；必须先冻结树再映射。区域边界、目录上限和用户固定类别永远高于 AI建议。

### 2.2 分类来源

固定模板：使用版本化模板树，用户可复制编辑。内置模板只读，修改生成用户版本。

用户指定类别：输入分行的类别路径或树形编辑器；模型只能选已有类别。未知／证据不足返回 abstain，不擅自扩展。

自然语言：把用户说明编译成结构化 ClassificationPolicy，展示解释、包含／排除标准和可能冲突；本地分层抽样后提出目录树。规则存在歧义时用安全默认并显示提醒，而不是凭空推断用户生活背景。

「AI 自动规划」不代表自动上传任意内容：必须先完成数据出站授权。仅输入规则可单独调用云模型编译，此时不发送文件内容。真正基于文件样本规划前需本次样本授权。

### 2.3 规则引擎

条件支持扩展名、文件名 contains／glob、父路径 contains、大小区间、模态、日期区间、可得的元数据值、已提取正文关键词。首版不开放任意脚本和复杂正则执行。

动作只有 `exclude`、`force_category`、`hint_category`。优先级按安全排除 → 用户人工指定 → 规则 exclude → 最小 priority 的强制规则 → AI建议。多个同优先级强制规则指向不同类别视为冲突，进入待确认；不能靠偶然数据库顺序选一个。

强制分类可以减少 AI调用，但不能绕过目标路径安全、文件前置条件或目录层级。提示规则不是事实，文件名中「发票」可被正文证据否定。

rules_only 不允许 auto_plan，界面要求使用固定模板／用户固定树。ai_first 仍尊重用户排除和强制分类，不为这些文件浪费调用；只是普通提示不先截断分类流程。

### 2.4 审阅状态，不伪造概率

系统计算 `review_band=high|medium|low` 和 `needs_review`。模型自评 `model_score` 可以存储但不作为实际正确率。

high 要求类别合法、证据引用可核对、必需模态已解析、无冲突且分数达到建议门槛 0.85；该门槛是启发式，不是校准概率。medium 表示有候选但证据弱／自评 0.60～0.85／存在次要警告。low 包含无法判断、解析失败、关键模态缺失、证据不支持或自评低于 0.60。

默认只有 high 自动进入执行候选；medium／low 保持原处，用户明确选类别后可放行。direct_move 不自动搬走 medium／low。人工选择记录为 manual_accepted，不伪造为模型高可信。

## 3. 文件操作四模式

preview_move：分类后停在审阅，用户确认经过校验的计划才执行。

direct_move：任务启动时明确批准操作范围、已确认的分类树和安全条件；系统仍持久化预览计划。发生新分类树、权限范围变化、目标变化、冲突或中低可信项时不扩大授权；跳过未授权项。它不支持「让 AI任意新建并移动」。

copy：源文件不动，只复制已通过审核项到另选输出目录；跨扫描范围递归回扫必须阻止。撤销复制仅处理本任务创建且未改变的副本。

report_only：扫描、分类、审阅与导出都可用，但不创建分类目录、不执行文件移动或复制。特别适合比较模型和测试规则。

所有执行模式默认 keep_both，不覆盖。可选 skip 同名文件。相同内容哈希也不自动删除／合并，仅标记疑似完全重复供查看。

## 4. 附加但首版必需的功能

| 功能 | 明确行为 |
|---|---|
| 暂停／取消 | 停止调度新工作，当前安全操作完成到检查点；取消不自动回滚已完成移动 |
| 断点恢复 | 重启先核对日志和磁盘状态；不简单把 RUNNING 改回运行继续 |
| 人工改类 | 单个／批量修改，保留旧建议与修改来源 |
| 类别调整 | 合并／重命名／移动节点都生成树的新版本，使旧计划失效 |
| 重新分析 | 可选择失败文件／选中文件；只重新计算受影响结果 |
| 缓存 | 内容摘要、解析器版本和参数命中时复用；跨文件名和区域的分类不能随意复用 |
| 样例试跑 | 前 20 个分层样例、report_only 默认，明确不是整批最终统计 |
| 文件查看 | 安全缩略图、转义文本、音视频受控预览；不执行 HTML／脚本／宏 |
| 历史 | 任务、版本、模型、已移动／跳过／冲突、撤销可用性 |
| 导出 | UTF-8 CSV 与 JSON；完整绝对路径导出前提示敏感性 |
| 资源检查 | OCR／ASR／ffmpeg／本地模型能力逐项标示；缺失能跳过相关分析 |
| 成本 | API调用数、token、已知估算费用、硬预算控制，不伪装未知价格为 0 元 |
| 同伴文件 | 唯一匹配的 JPG+XMP、视频+SRT／ASS、音频+LRC 可成组跟随；歧义不自动处理 |

## 5. 首版不做与后续边界

不做模型训练、账号权限体系、向量数据库、全文语义搜索、网盘同步、后台目录监听、自动删除重复文件、自动清理旧文件、复杂重命名工作流、压缩包解包整理、代码工程内部拆分、身份识别人脸库。数据库和解析器接口可扩展，但不得为了「以后可能需要」先开发平台化复杂框架。

## 6. 三个验收用例

校园资料：在保留一级目录模式下，对「课程／活动」各区域分别整理；课程里的讲义 PDF、课堂录音、作业截图可按相同科目聚合，不跨到活动目录。没有课程证据的文件保留待确认。

下载文件夹：在 recursive + 模态优先下输出最多两级；ZIP／EXE 默认原地，图片和文档生成预览；重复运行没有新文件时不继续嵌套分类目录。

旅行资料：在 topic_first + 用户指定目的地类别下，把 PDF行程、照片、视频关联到有证据的旅行。仅凭沙滩不猜城市；EXIF缺失且文档没有地点时选择主题级类别或待确认，而不是虚构目的地。
