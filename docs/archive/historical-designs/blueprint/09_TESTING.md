# 测试策略、样本与验收标准

> **历史测试提示：** 模板/规则测试项已被 AI-only、旧任务兼容与任务记录删除安全测试取代；保留原编号仅用于追溯。

## 1. 分清四种证据

设计包契约检查、应用自动化测试、真实模型联调、Windows EXE实机验收是四件不同的事。前一种通过不能代替后一种。测试报告必须写清运行环境、输入样本、版本、命令、结果和没有验证的部分。

测试只使用临时目录或 `artifacts/test-workspaces`。不得默认扫描用户桌面、下载目录或源代码工程。所有文件变更测试使用拷贝或程序生成的样本，测试前后保存清单与SHA-256。

## 2. 分层测试

| 层 | 工具／范围 | 验证 |
|---|---|---|
| 领域单元 | pytest | 状态机、规则、采样、树约束、plan hash、等级政策 |
| 性质测试 | Hypothesis | 任意路径／类别名不能越界，碰撞处理确定且不覆盖 |
| 存储集成 | SQLite临时库 | 外键、唯一约束、迁移、事件顺序、幂等 |
| 解析集成 | 实际小样本 | 格式识别、覆盖度、错误与资源限制 |
| 模型契约 | 本机假HTTP服务 | 成功／坏JSON／429／超时／401／图片不支持／取消 |
| 文件安全 | 实际临时磁盘目录 | 无覆盖、跨卷、崩溃点、恢复、撤销冲突 |
| 前端组件 | Vitest | 状态、权限、选择、批量范围与错误提示 |
| 浏览器流程 | Playwright | 全流程UI、分页、键盘、响应宽度、长中文名 |
| 桌面集成 | Windows原生运行 | 目录选择、WebView2、关闭、worker、不弹多窗口 |
| 发行包 | 干净Windows用户环境 | 无Python／Node运行、资源查找、卸载保留数据 |

假服务只验证协议，不评分真实模型的语义能力。跨卷测试必须真有两个卷，临时目录里的两个子文件夹不算跨卷。浏览器E2E不算pywebview窗口实测。

## 3. 核心测试编号

### 文件与路径

FS01 三扫描模式精确文件集合；FS02 preserve_top_level禁止跨区域；FS03 root_loose不侵入保护区域；FS04 1／2／3级相对区域计算；FS05 输出排除与重复整理不无限嵌套；FS06 Unicode／中文／大小写／保留名；FS07 junction／symlink／reparse与源身份变化；FS08 项目目录与系统目录保护。

FS09 同名保留双份且预览等于实际；FS10 批次内目标碰撞；FS11 批准后目标出现必须阻塞；FS12 源内容变化使计划失效；FS13 不支持格式原地保留；FS14 同伴文件组完整与歧义处理；FS15 文件锁定／只读／卷断开；FS16 特殊数据流／硬链接／云占位警告。

### 执行与恢复

OP01 report_only无磁盘分类目录改变；OP02 copy源hash不变；OP03 同卷move no-clobber；OP04 跨卷copy-verify-publish-delete顺序；OP05 每个检查点注入进程终止后恢复；OP06 重复execute幂等；OP07 取消保留已提交操作；OP08 撤销move不覆盖原路径；OP09 撤销copy仅处理本任务且未变化副本；OP10 重复undo幂等；OP11 磁盘满保留源；OP12 数据库日志提交失败后停止破坏性动作；OP13 新出现目标不临时改名绕过批准；OP14 partial group报告不假装原子成功。

### 分类与解析

CL01 24模板schema／无环／深度／兄弟数；CL02 模态优先深度1无隐藏第二层；CL03 强制规则优先和同级冲突；CL04 rules_only拒绝auto_plan；CL05 分类只能引用当前树类别；CL06 abstain与其他不同；CL07 自评分不能单独放行；CL08 外部内容提示注入无效；CL09 变更树使旧plan失效；CL10 人工review不改写AI历史；CL11 缓存上下文隔离。

PA01 TXT／MD／JSON／CSV；PA02 文本PDF与扫描PDF；PA03 DOCX表格与PPTX标题；PA04 XLSX公式不执行、缺缓存提示；PA05 图片OCR／方向／去EXIF缩略图；PA06 GIF多帧；PA07 音频转写／静音／低质量；PA08 视频均匀帧与时间戳；PA09 采样覆盖度正确；PA10 超大图／损坏／加密／解压炸弹限额；PA11 组件缺失降级不造假；PA12 worker超时清理仅限自有作业。

### 模型与隐私

AI01 DeepSeek文本真实小样本；AI02 DeepSeek图片真实小样本；AI03 Qwen文本与视觉实际服务；AI04 JSON修复上限；AI05 401不重试／429尊重Retry-After；AI06 本地模式零云请求；AI07 协议不支持图像时显示限制；AI08 model_id或URL改变使能力失效；AI09 调用预算含修复与重试；AI10 未授权数据无法通过出站Gate；AI11 不记录Key、base64、正文或思维链；AI12 LAN与loopback隐私标签准确。

### UI与桌面

UI01 新建表单默认值来自后端；UI02 预览双路径与真实计划一致；UI03 全选当前页／全部筛选区分；UI04 取消／暂停文案与状态一致；UI05 等待、空、失败、预算耗尽可恢复；UI06 1024／1280／1440宽度与高DPI；UI07 键盘操作与不只靠颜色；UI08 页面不出现伪数据成功状态；UI09 证据抽屉转义HTML；UI10 关键危险动作确认与plan hash。

DT01 原生目录选择；DT02 单实例与端口安全；DT03 主窗口关闭安全暂停；DT04 worker不弹GUI；DT05 无运行时环境启动EXE；DT06 缺WebView2提示／安装；DT07 onedir移动位置后资源查找；DT08 不写安装目录；DT09 日志与凭据清理不泄露用户内容。

## 4. 样本集

程序生成的确定性样本集至少覆盖：所有核心扩展名、中文名、空文件、同名文件、长路径、嵌套文件夹、只读、内容相同但路径不同、假扩展名、不支持格式。附带expected_manifest.json标明每个文件的用途和预期，不把随机AI输出当正确答案。

语义评测使用单独的人工作标样本，建议首轮120份：图片、文本、PDF、Office、音频、视频各20份，包含容易和模糊样本。每份记录可接受主类别集合、应否弃判、证据来源与许可。音视频样本需有真实可用内容，不能只用空文件冒充覆盖。

若没有用户允许的真实样本，先用自造／明确许可的示例完成技术测试，把语义质量标为待验证。不得自动拿个人目录作为金标准。

## 5. 语义质量指标

分别报告：全量准确率、macro-F1、高可信自动放行项精度、自动覆盖率、弃判率、每模态错误数、坏JSON比例、每文件调用数／token／时延。人工认可的多类别集合按集合命中计算，模糊样本不强行给唯一错误标签。

试用目标：高可信放行精度≥95%，有效样本主类macro-F1≥0.85，自动覆盖率不低于60%。这些是初始调优目标，不是已实现承诺，也不能在很小样本上宣称普遍准确率。达不到时收紧放行政策、调整模板和证据要求，保留更多人工审阅，不以提高模型自评分伪造通过。

对云／本地两个模型使用同一文件快照、模板、解析档位与隐私设置，比较报告不能一边看全文一边只看首段后宣称模型差距。测试费用与样本数量由用户允许范围控制。

## 6. 性能测量与目标

第一版以10,000个文件metadata扫描、5,000行审阅列表、100份多模态小样本为基线。记录硬件、磁盘、暖／冷缓存、文件总字节、模型运行时与上下文配置。

目标是列表交互不明显卡顿、普通页面响应大多在200ms以内、元数据扫描不等待大文件全量hash；扫描吞吐／OCR／ASR／Qwen速度由真实环境测量，不写未经测量的固定“每秒几百文件”宣传。峰值内存分别统计主程序、WebView与解析worker，模型服务独立列出。

## 7. 验收命令与脚本要求

阶段01建立scripts/verify.py，支持unit、safety、parsers、models、ui、all范围；缺少当前阶段尚未创建的可选能力不应默默PASS，报告NOT_IMPLEMENTED。阶段出口用对应范围，发布前用all。

约定命令：`python -m pytest backend/tests`、`npm --prefix frontend run typecheck`、`npm --prefix frontend run test -- --run`、`npm --prefix frontend run build`。具体脚本必须在阶段01落地，不能在报告里写从未存在的命令“已通过”。

用户当前机器没有Windows桌面自动化或真实模型时，相关项标BLOCKED_EXTERNAL并继续不依赖它的测试。任何安全必需项失败，发行包不能标为正式可操作真实文件的版本。
