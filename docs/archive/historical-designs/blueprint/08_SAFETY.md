# 文件安全、操作日志、恢复与撤销

## 1. 不变量

1. 默认不覆盖任何既有文件；第一版没有overwrite模式，也不做自动永久删除。
2. AI只选择类别ID；目标路径由执行计划编译器根据授权root与合法category segments生成。
3. 任何文件改变前，操作意图已写入持久日志；原目录之外的读写只限任务授权范围与应用自有临时目录。
4. 移动成功的定义包含目标存在、内容核验与记录提交，不能仅凭API无异常；跨卷移动在目标核验完成之前不得删源。
5. 恢复与撤销都以磁盘现状为准；发现外部修改、不明文件、同名占用时停止相关项，绝不猜测性覆盖。

这些措施降低风险，不替代用户重要文件的独立备份。软件无法对硬盘物理损坏、断电后文件系统损坏或其他程序恶意并发修改作无条件恢复保证。

## 2. 路径安全与授权

原生目录选择器注册 source_grant，记录规范路径和卷信息。扫描与执行均检查每级路径组件：拒绝符号链接／junction／reparse point、设备路径、ADS冒号、目录穿越、UNC／网络路径首版操作、应用数据目录和系统目录。不能用简单字符串startswith判断路径归属，应比较规范化路径组件及实际文件句柄解析结果。

类别名称先做Unicode NFC规范化，拒绝空名、`.`／`..`、分隔符、控制字符、Windows保留名、尾部点或空格以及非法字符。每段最多60字符；完整路径超过本次实测支持能力时阻塞，不能截断后继续。不要把路径变成小写后写回磁盘；比较键和展示名称分开。命名与Windows限制依据S13。

root_loose不能目标指向被保护的一级区域。输出在源目录下时必须在扫描前排除；从前次任务知道的输出目录不重复嵌套。源=目标的文件标记noop。目标是源的同一路径或硬链接别名时不复制覆盖；硬链接／多链接文件默认跳过并告警，等待用户在副本上处理。

文件读取和执行之间有TOCTOU风险：执行前获取Win32句柄、核对volume serial/file index、size、mtime、hash，禁止共享写入以减少竞争。使用句柄完成的移动／删除优先于重新解析字符串路径。若所选文件系统不能提供足够的身份或锁语义，保守降级为只复制或要求人工处理，不宣传为同等安全。

## 3. 计划编译与冲突规则

所有最终文件名在编译计划时确定，用户预览看到的就是计划目标。分类不改原basename；同名冲突keep_both在扩展名前加 ` (2)`、` (3)`，在稳定排序的文件ID顺序下分配，考虑大小写不敏感碰撞与同批次目标碰撞。

默认不按哈希去重删除。同名同哈希仍可保留两个副本或由用户选择skip。同伴文件组按同一主stem统一冲突后缀，例如 `video (2).mp4` 与 `video (2).srt`。不能只改主文件却失去配对。

批准后有人新建同名目标，操作返回TARGET_APPEARED并停止该项；不能临时再加后缀后继续。用户重新生成计划后再执行。余额／空间／权限变化也需要重新检查。

## 4. 固定操作状态机

状态允许：PLANNED、PREPARED、COPYING、TEMP_WRITTEN、VERIFIED、PUBLISHED、SOURCE_REMOVED、COMMITTED、SKIPPED、FAILED、CONFLICT、UNDO_PREPARED、UNDONE、UNDO_CONFLICT。

每次状态变更同步追加operation_event。磁盘动作与数据库提交不能合成一个事务；每个磁盘动作前后都有可核对的检查点。数据库提交失败后不要继续下一步破坏性操作。

### 4.1 同卷移动

写PREPARED，保存源身份和完整SHA-256、批准目标、父目录检查结果。创建必要目录并记created_directories；使用Windows无覆盖的原子重命名／句柄重命名将源发布到目标。不要使用会覆盖目标的os.replace。

目标发布后核对文件身份和预期hash，写PUBLISHED，再写COMMITTED。源路径应消失。若在rename后、日志更新前崩溃，恢复服务可以由「源缺失、目标身份/hash吻合」补齐提交；不能再执行一次移动。

### 4.2 复制与跨卷移动

1. 记录PREPARED；再次核对源；目标同卷临时文件使用唯一 `.guixu-part-{operation_id}` 且以exclusive create创建。
2. 写COPYING，分块复制并计算hash；检查取消旗标只在块边界，不把半文件当完成。
3. flush并fsync临时文件，写TEMP_WRITTEN；重新读回hash确认字节一致，写VERIFIED。确保复制过程中源身份／内容未变化。
4. 以不覆盖原子发布临时文件至批准目标，写PUBLISHED。默认尽力保留mtime等可支持元数据；跨卷ACL／ADS／扩展属性完整保真不作承诺，发现非默认数据流或特殊属性时首版移动阻塞、允许用户选择只复制普通数据并显示限制。
5. copy模式至此写COMMITTED，源始终保留。
6. 跨卷move再次锁定并核对源，确认目标hash仍有效后才删除本次源文件，写SOURCE_REMOVED，再写COMMITTED。

跨卷方案实际占用额外目标空间，执行前预估剩余文件字节 + min(5%,2GiB)安全余量；执行中也检测磁盘满。只有严格归属当前任务的未发布临时文件可自动清理。

### 4.3 同伴组

主文件与唯一匹配的sidecar构成逻辑组，预检整组；同卷逐项移动失败时尝试撤回已完成项，遇冲突就将整组标PARTIAL_GROUP并交给恢复流程。跨卷先复制并验证整组，再发布整组、最后删源。文件系统不提供多文件原子事务，UI不能显示「整组绝对原子」。

## 5. 崩溃恢复判定表

| 源 | 最终目标 | 自有临时文件 | 处理 |
|---|---|---|---|
| 存在且原hash | 不存在 | 不存在 | PREPARED可重新执行 |
| 存在且原hash | 不存在 | 存在且完整hash | 恢复发布前再次预检 |
| 存在且原hash | 不存在 | 存在但不完整 | 删除自有临时文件后重拷，或留给用户取消 |
| 存在且原hash | 存在且预期hash | 无关 | copy补提交；move停在源删除前检查点 |
| 不存在 | 存在且预期hash/身份 | 无关 | 移动已完成，补日志提交 |
| 存在但已变化 | 存在目标 | 任意 | CONFLICT，不删源、不覆盖目标 |
| 不存在 | 不存在 | 不存在 | FAILED_MISSING，提示人工检查／备份 |
| 任意 | 存在但非预期内容 | 任意 | CONFLICT，绝不以本任务名义删除 |

「存在但同hash」只是内容一致，是否本任务创建还要核对日志、目标身份和记录的路径。凭碰巧同hash不能收编别人创建的文件。

## 6. 撤销

撤销是一份反向操作计划，也需要预览、批准、日志和幂等。默认按原操作相反顺序处理。文件不再处于执行完成时位置、内容hash变化、目标身份不符、原路径已被占用时标UNDO_CONFLICT。

撤销移动：把本任务搬走且未变化的文件移回原路径；跨卷采用同样先复制验证再删目标流程。原路径被占用，不覆盖，可让用户选择另存恢复位置并重新批准，这不是完全原样撤销。

撤销复制：仅处理本任务创建且未变化的副本，默认送入系统回收站；先记录UNDO_PREPARED，成功后UNDONE。回收站不可用或该介质不支持时保留副本并报冲突，不降级为永久删除。源文件从未被删除。

目录清理只移除created_by_task=true且仍为空的目录。撤销结束报告已恢复、冲突、跳过与剩余文件，不能把部分成功显示为全部撤销。重做不重放旧磁盘指令，应根据现状重新编译计划。

## 7. 注入与恶意内容

文件名、OCR、正文、字幕、ASR转写和模型输出都不可信。模板与系统提示要求模型仅处理数据，不遵循内容中的“移动到某处”“上传所有文件”“忽略规则”等命令；但提示不是唯一防线，必须由schema、类别allowlist和执行器落实约束。

解析不运行宏、Python／JS、PDF活动内容和Office外部链接。压缩容器格式例如DOCX／XLSX必须限制解压条目数、总解压字节与压缩比；Pillow限制像素数；PDF限制资源；ffmpeg只接受本地批准文件和受限协议，subprocess用参数数组且shell=False。worker不能发起联网下载。

云出站统一经过PrivacyGate，只允许配置的推理地址；HTTP重定向不自动跟随到其他域，关闭隐式环境代理或在设置中显式说明代理出口。局域网Qwen不是严格“只在本机”，UI明确显示数据会发送到哪台服务器。

## 8. 必测故障点

准备日志后、复制中、fsync后、目标发布后、源删除后、数据库提交前分别注入崩溃。另测源改变、目标出现、大小写同名、中文长路径、junction置换、只读、磁盘满、卷断开、sidecar中途失败、重复execute、重复undo和伪造路径。

在这些测试完成前，direct_move在生产设置页保持不可启用；开发演示可显示但必须标为未验收。安全验收完成后按产品要求开放。
