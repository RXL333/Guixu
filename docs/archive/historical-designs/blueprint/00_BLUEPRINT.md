# 归序 Guixu｜完整开发蓝图

> **历史基线提示：** 本文中的分类模板、规则优先和多模式入口已由 2026-09-20 的 Conversation Agent 方向取代。当前运行时以 AI-only 和 `docs/LEGACY_PRODUCT_CLEANUP.md` 为准；本文保留用于追溯早期决策。

## 0. 使用方式与权威顺序

本项目是单用户 Windows 本地桌面软件，不是多租户网站。用户不需要部署后端服务、打开终端或安装 Python／Node 才能使用最终发行版。开发者用现代 Web 技术构建界面，再由 Python桌面外壳承载。

本文件负责总览；具体行为以对应专题文档为准。产品语义由 01 定义，安全行为由 08 定义，接口与数据分别由 07／03 定义，机器契约与这些文档必须同步。冲突不许自行选择更省事的一边：在当前阶段修正契约并记录决策。

## 1. 产品承诺

选择一个文件夹，说明想怎样整理，先了解内容、规划分类，再显示每个文件将发生什么。用户决定是否移动、复制或只看报告。每一步能暂停、解释和追溯；可逆操作在文件未被外部更改等前提下可撤销，不能保证任意情况下无条件恢复。

项目内部名称「归序 Guixu」只作为开发代号，发布前可修改展示名称，不改变模块边界和数据格式。

## 2. 已冻结的关键决策

| 维度 | 规定 |
|---|---|
| 平台 | Windows 11 x64 为验收主平台；Windows 10 兼容性另测，不宣称未测系统受支持 |
| 文件范围 | 图片、文本、PDF／现代 Office、音频、视频；其他文件仅元数据识别、默认不移动 |
| 操作 | preview_move 默认；direct_move 高级；copy；report_only |
| 扫描 | current_only、recursive、preserve_top_level；默认第三种 |
| 整理策略 | modality_first、topic_first、hybrid；默认 hybrid |
| 分类来源 | 固定模板、用户指定类别、自然语言自动规划；默认自动规划 |
| 分类引擎 | rules_first 默认、ai_first、rules_only |
| 目录约束 | 每个整理区域内默认最多 2 级，可选 1～3；同级 12 默认、最多 20；每区域最多 80 个节点 |
| 全任务新目录上限 | 默认 200，超出需减少类别／分批，不静默无限扩张 |
| 待确认 | 虚拟待办，不默认移动；用户可显式选择送入实体「待确认」目录，该目录计入层级和数量限制 |
| 处理链 | 元数据／确定性规则先行，必要时本地解析，再规划、分类、编译执行计划 |
| 隐私 | 云端最小上传；首次分析前授权；原文件上传关闭；本地模式禁止静默云回退 |
| 模型 | DeepSeek 云服务、本地 Qwen 服务；模型身份与推理运行时分开配置 |
| 数据 | 本机 SQLite + 文件缓存；Key 存 Windows 凭据管理器 |
| 执行器 | 永不覆盖；无自动删除；先写操作日志；失败／外部修改可产生撤销冲突 |
| 首发不做 | 文件监控常驻、多人账号、云盘同步、模型训练、工作流编辑器、自动去重删除、全硬盘扫描 |

以上默认值也必须出现在 seed/default-settings.json 和 TaskSettings 契约中，不能另写一套前端默认值。

## 3. 用户最常用的一条路径

新建任务 → 选择源目录和输出方式 → 使用默认「保留一级目录／智能混合／规则优先」 → 选择模板或输入要求 → 确认本次可上传的数据种类 → 只读扫描与本地分析 → 审阅分类树 → 确认树 → 批量分类 → 审阅待确认项与冲突 → 确认执行计划 → 串行文件操作 → 报告与撤销入口。

纯规则和固定模板可跳过 AI规划；report_only 在生成报告后结束。direct_move 不是让模型直接操作磁盘：用户在启动时授权当前冻结配置，系统仍生成、持久化并校验完整计划；不确定或冲突项留在原处。自动规划产生的新分类树仍要确认；要真正无人值守，必须使用已确认模板／固定分类树。

## 4. 技术栈定稿

| 层次 | 选型 | 在本项目的职责 |
|---|---|---|
| 前端 | Vue 3 + TypeScript + Vite + Pinia + Vue Router | 桌面工作台与状态呈现 |
| 控件 | Naive UI + lucide-vue-next + 自定义 CSS | 无障碍基础控件、图标、专属视觉 |
| 桌面 | pywebview，明确使用 EdgeChromium | 原生目录选择、窗口与安全启动 |
| 本地 API | FastAPI + Uvicorn，单服务实例 | REST 与长任务编排 |
| 类型与存储 | Pydantic v2、SQLAlchemy 2、Alembic、SQLite | 契约、事务、迁移 |
| 网络 | httpx | 调用两类 OpenAI-compatible Chat Completions 服务 |
| 文本解析 | charset-normalizer、csv／json 标准库 | TXT、MD、JSON、CSV |
| 文档解析 | pypdf、pypdfium2、python-docx、python-pptx、openpyxl | 提取文字／结构，必要时渲染 PDF |
| 图片／OCR | Pillow、RapidOCR + ONNX Runtime CPU | 安全缩略图、EXIF、文字提取 |
| 音视频 | ffprobe／ffmpeg、faster-whisper CPU INT8 | 元数据、抽帧、可选离线语音转写 |
| 系统与密钥 | platformdirs、keyring、psutil、Windows文件句柄接口 | 数据目录、密钥、资源检查、移动安全 |
| 测试 | pytest、Hypothesis、Vitest、Playwright | 领域、契约、组件与浏览器测试 |
| 发布 | PyInstaller onedir + Inno Setup | 可运行目录包与安装版 EXE |

这是工程选择，不意味着每个依赖的最新版本已经完成组合测试。阶段 01 解析实际依赖并生成锁文件；新增 OCR／ASR依赖在阶段 03 单独验证。详细官方依据见 12。

## 5. 不得遗漏的核心设计

文件一律有稳定 file_id，不用路径作为业务主键；路径会因移动改变。分类目录有 category_id，AI只能选 ID。分类树、解析参数、模板、规则、模型配置和执行计划均带版本或摘要。批准的是一个确定的计划哈希，不是「任何后续计划」。

默认不把模型自报的 0.95 显示成「95% 正确」。展示「高／中／低可信建议」及证据是否充足；自评分仅在详情作为未校准信号。原生视觉能力不等于运行时支持图像接口；连接测试要分别探测文本、图片、JSON、取消和错误处理。

一份文件只进一个物理主目录，跨主题信息记录为标签。图片里的「人物」只是内容类别，不做人物身份识别、敏感属性猜测或仅凭模糊风景猜城市。没有能可靠支持分类的证据就弃判。

## 6. 页面结构

六个主导航：整理工作台、分类模板、规则中心、任务记录、模型连接、设置。工作台内部包含新建、扫描、分类树、审阅、执行和报告六种任务视图，不额外堆一组无业务价值的统计大屏。

视觉方向为「数字档案室」：深墨绿导航、暖纸白工作区、清晰文件行、实体档案标签与细线目录树。识别特征是审阅页的「原位置 → 新位置」双向路径排版，以及右侧随选择变化的分类依据栏。详细页面规格在 06，静态参考在 ui。

## 7. 开发顺序与出口

先做真实文件系统的安全边界和确定性闭环，再加入解析器和模型。不能把整个平台先做成假数据页面后才发现执行逻辑不可用。

九阶段为：基础与扫描 → 安全执行 → 多模态解析 → 模板规则与规划 → 双模型 → 完整页面 → 恢复与缓存 → 验收 → 打包。总 Goal 允许顺序推进，分阶段 Goal 允许独立控制成本。

## 8. 成功的定义

在测试目录中，图片、TXT／MD、PDF、DOCX、PPTX、XLSX、音频、视频能按各自能力获得 FileProfile；模板和自然语言规则可工作；三种整理策略／扫描方式和四种操作方式有测试覆盖；预览与实际执行一致；重复请求不重复移动；中断后能判定磁盘状态；撤销不覆盖用户后续文件；断网时不会偷偷把本地任务转云端。

发布产物必须在未安装 Python／Node 的 Windows测试环境运行；真实云／本地模型联调、浏览器 UI 测试和 EXE冒烟测试分别列证据。没有对应环境或 Key 的项标为外部阻塞，不影响已完成部分的诚实交付。
