# Guixu Post-1.0 Backlog

2026-09-29 建立。本文记录 `RELEASE_ACCEPTANCE.md`「1.0 明确放弃」中被裁剪的项目，附带裁剪理由、1.0 内的替代约束，以及重新纳入门禁时需要的证据。

裁剪的目的是让"1.0 能不能发"成为一个有边界、可回答的问题。把所有"没测"的项目都算作阻塞，等于没有门禁；把它们悄悄算作通过，则是自欺。这里的每一项都写明了**为什么现在不做**和**1.0 里用什么保证不出事**。

> **2026-09-29 更正。** 本文初版曾把「PDF 内容解析」和「Office 文档解析」列为 1.0 放弃项，理由是"未实现"。这个前提是错的：`infrastructure/parsers/documents.py` 已实现 pypdf / python-docx / python-pptx / openpyxl 与本地 RapidOCR 扫描件 OCR，且 `tests/parsers/test_parsers.py` 的 `test_pa02`~`test_pa04`、`test_pa10` 覆盖文本/扫描/加密 PDF、DOCX 表格、PPTX、XLSX 公式不执行与 zip bomb 限额。已实现且已有回归的功能不能靠"声明不支持"来卸责，两项已从裁剪清单移除，改回门禁范围；`RELEASE_ACCEPTANCE.md` 中长期标着 `NOT_TESTED` 的 PDF/Office 两行是**过期记录**，同时更正。

## 1. 真实供应商故障注入（D04/D06/D08/D09/D10/D12 的真实侧）

**裁剪理由**：DeepSeek 的 401、429、5xx 与畸形输出无法确定性制造——要么需要作废凭据，要么需要控制供应商，要么依赖模型随机性。相同代码路径已由 `MockTransport` 回归覆盖（验证 401 不重试、遵循 `Retry-After`、503 后有界 3 次尝试并返回 `MODEL_SERVER_ERROR`、保留状态码并标记 retryable）。

**1.0 内的替代约束**：代码路径契约必须为 PASS。真实调用中若出现异常输出，按现场证据登记缺陷，不预设门禁。

**重新纳入需要**：一个可控的模型桩服务（非 Mock 类，能返回真实 HTTP 状态码与畸形 body），加上针对 429 `Retry-After` 与持续 5xx 的集成回归。

## 2. 消息量滚动性能（P05–P07：100/300/500 条消息）

**裁剪理由**：属于体验优化而非安全或正确性问题；消息列表已按页加载（`test_phase_m_workspace_interactions` 覆盖"加载下一页并搜索初始页之外"）。

**1.0 内的替代约束**：长会话打开不得丢失或重复消息。10 轮以上的一致性由 P08 覆盖（revisions、current plan、latest execution、references 必须互相一致）。

**重新纳入需要**：在打包版 WebView 中测量 500 条消息的首屏时间、滚动帧率与内存占用。

## 3. 键盘可达性全量验收（U09）

**裁剪理由**：完整的键盘导航与焦点陷阱验收需要可用性测试流程与真实桌面投入，超出 1.0 范围。

**1.0 内的替代约束**：关键操作（批准、执行、撤销）必须可点击，且带 `title` 或可见文本说明。

**重新纳入需要**：Tab 顺序遍历、Enter/Space 激活、Esc 关闭、焦点陷阱与可见焦点环的自动化回归，加上人工评审。

## 4. 可访问性全量验收（U10）

**裁剪理由**：对比度与"减弱动效"需要设计与人工评审，不是可以靠回归套件关掉的门。

**1.0 内的替代约束**：不引入无法辨识的颜色作为唯一状态区分——每个状态都要有文字或图标佐证。

**重新纳入需要**：axe 类自动检查 + 对比度实测 + `prefers-reduced-motion` 下的样式核对。

## 5. 代码签名与公网分发

**裁剪理由**：无签名证书。代码签名需要购买证书并走验证流程，不在工程范围内。

**1.0 内的替代约束**：未签名版本在发布说明中写明会触发 Windows SmartScreen；1.0 以受控分发（内部下载或已知来源）交付，不做公网上架。

**重新纳入需要**：购买代码签名证书、完成 EV 验证、签名 onedir 与安装器、验证时间戳与双击无警告。

## 6. 非 Windows 平台

**裁剪理由**：产品定位是 Windows 桌面文件整理器。测试套件本身就依赖 Win32 句柄、Credential Manager、reparse point、长路径与跨卷取消——Linux 上行为不同，CI 强制 `windows-latest` 是刻意的。

**1.0 内的替代约束**：无。

**重新纳入需要**：抽象 Win32 专属层、补平台适配层、在 CI 增加矩阵。这是一项结构性工作，不是补测试。
