# 性能改进实施计划（2026-09-27）

目标：缩短大目录首次关联与恢复核对耗时，避免大方案一次渲染数千行，同时保持路径范围、文件指纹、版本化计划和执行前重验证。

1. 文件关联：对大量文件的路径检查和指纹读取使用有界工作线程；数据库读取、事务写入及结果顺序保持原样。验证越界文件整批拒绝、文件指纹完整、500/1,000/5,000 项基准。
2. 恢复核对：保持完整文件状态判断，仅合并数据库更新，减少逐条往返。验证外部修改、移动、丢失与无变化重开。
3. 大目录界面：源文件 API 支持分页与目录内搜索，逐文件方案按页显示并保留全量搜索、图片预览与数量提示。验证源文件第二页和搜索、5,000 项方案仅渲染当前页且末项仍可查阅。
4. 完成后运行相关测试、完整前后端回归和性能对比，更新阶段报告与项目状态。真实照片和用户目录不作性能压测。

本轮不改变模型批大小、文件执行语义或发布就绪结论。首次分析进度流和真实 WebView 帧率需要单独的端到端测量基础，记录为后续工作。
